# Audio Bridge

Я сделал это, чтобы гонять звук с компьютера на телефон (и обратно — с телефона на компьютер идёт
микрофон) с минимальной задержкой, тремя способами на выбор: Wi-Fi, USB и Bluetooth. Полный дуплекс,
без плясок с виртуальными аудиоустройствами и сторонними приложениями с рекламой.

- `pc-server/` — сервер на .NET 8 / WinForms (NAudio для WASAPI, Concentus для Opus, InTheHand.Net.Bluetooth для RFCOMM, WinRT для Bluetooth LE, libusb+UsbDk для USB)
- `android-app/` — Android-приложение на Kotlin + Jetpack Compose/Material 3 (минимум Android 8.0 / API 26)
- `installer/` — Inno Setup скрипт и билд-скрипт для установщика ПК-сервера

Формат протокола между ПК и телефоном и почему кодеки выбраны именно так — в [PROTOCOL.md](PROTOCOL.md).

## Быстрый старт

### 1. ПК-сервер

**Готовый установщик** (проще всего): `installer/output/AudioBridgeServer-Setup.exe` — самодостаточный
exe, .NET рантайм зашит внутрь, ничего доустанавливать не нужно. Ставится без прав администратора в
`%LocalAppData%\AudioBridge`, кладёт ярлыки в меню Пуск и опционально на рабочий стол/автозагрузку.

Собрать установщик самому:
```powershell
powershell -ExecutionPolicy Bypass -File installer\build.ps1
```
(нужен Inno Setup 6 — `winget install JRSoftware.InnoSetup`).

**Или запусти из исходников:**
```bash
cd pc-server/AudioBridge.Server
dotnet run
```

Окно сервера оформлено так же, как приложение (светлая и тёмная темы, по умолчанию как в Windows): слева большая кнопка «Старт/Стоп» со статусом и списком подключённых телефонов, справа карточки «Звук», «Подключения» и «Лог».

В окне сервера:
1. Выбери устройство, с которого захватывать звук (или оставь "по умолчанию").
2. Выбери устройство, куда выводить микрофон телефона.
3. Нажми **Старт** — поднимутся TCP-слушатель (Wi-Fi), USB-хост (кабель), Bluetooth-слушатель и UDP-responder
   для автопоиска сервера из приложения.

### 2. Android-приложение

Установи APK (провод или уже подключённый Wi-Fi-adb):
```bash
adb install -r android-app/app/build/outputs/apk/release/app-release.apk
```
Либо открой `android-app/` в Android Studio и нажми Run.

Приложение не в Play Store, поэтому обновляется само: при запуске проверяет
[GitHub Releases](https://github.com/RRZHD/audio-bridge/releases) этого репозитория, и если там
тег новее установленной версии — показывает баннер "Обновить" (качает .apk из релиза и передаёт
системному установщику). Чтобы выпустить новую версию, подними `versionName`/`versionCode` в
`android-app/app/build.gradle.kts` и опубликуй релиз с тегом `vX.Y.Z` и .apk-ассетом:
```bash
gh release create vX.Y.Z android-app/app/build/outputs/apk/release/app-release.apk --title vX.Y.Z --notes "..."
```

Интерфейс — Jetpack Compose, оформление взято из консоли менеджера (токены, радиусы, плашки, пилюли), две темы
(светлая и тёмная, по умолчанию — как в системе). Главный экран — одна большая кнопка включения со статусом и
подсказкой, под ней способ подключения пилюлями (Wi-Fi, USB, Bluetooth LE, Bluetooth) и компактная карточка выбранного
способа; на широком экране (альбомная ориентация) — две колонки. «Настройки» — отдельный экран: звук одним выбором
(Баланс / Малая задержка / Стабильность), тема, качество по Wi-Fi, а тонкая настройка (буфер, битрейты, частота) —
в свёрнутом «Дополнительно». Включить и выключить можно и без приложения: плитка «Audio Bridge» в шторке быстрых
настроек (долгое нажатие на шторке → «Изменить» → перетащить плитку), опция «Подключаться при запуске» и автозапуск
при подключении USB-кабеля.

### 3. Подключение

**Wi-Fi** — ПК раздаёт Wi-Fi (Mobile Hotspot). Выбери в приложении режим Wi-Fi — оно само разошлёт
UDP-broadcast и покажет список найденных серверов в сети (имя ПК + IP); тапни на нужный. Вводить IP
вручную нужно только если автопоиск ничего не нашёл (другая подсеть, файрвол и т.п.) — под списком
есть поле для этого.

**USB** — просто воткни телефон кабелем в ПК, где запущен сервер. Никакого adb, отладки по USB и
режима модема не нужно: сервер сам находит телефон на шине, переключает его в режим *Android Open
Accessory* (AOA — штатный механизм Android для «аксессуаров») и открывает с ним bulk-канал.
Android в ответ сам запускает приложение (при первом подключении ответь «Всегда открывать»), оно
переключается в режим USB и подключается без нажатий. Звук идёт без сжатия.

Один раз на ПК нужен драйвер **UsbDk** (подписанный, Apache-2.0): без него Windows не даёт
пользовательской программе обратиться к телефону, пока тот числится у системы как MTP/RNDIS.
Установщик предлагает его галочкой (запросит права администратора), в сервере есть кнопка
«Настроить USB». Заодно прописываются правила UsbDk «скрывать» устройства `18D1:2D00/2D01/2D04/2D05` (телефон в режиме
аксессуара): без них UsbDk перехватывает устройство перезапуском порта, а это выбрасывает телефон из режима
аксессуара. После установки нужна перезагрузка Windows — фильтр UsbDk цепляется
к USB-хабам при их старте.
Побочный эффект режима аксессуара: пока идёт сеанс, телефон не показывается как накопитель (MTP).
Не нужно — сними галочку «USB-кабель» в сервере.

**Bluetooth LE (режим «BT LE», рекомендуется)** — без сопряжения: в приложении выбери «BT LE» и «Подключиться», телефон начнёт
ждать, а запущенный сервер на ПК сам найдёт его и подключится (нужен Bluetooth на ПК, Windows 10/11). Задержка ~100–150 мс, без
провалов даже при полном битрейте: LE-соединение идёт по расписанию, которое радио обслуживает раньше, чем фоновое
сканирование других приложений.

**Bluetooth классический («BT»)** — запасной вариант: сначала спарь телефон и ПК как обычно через настройки Bluetooth (это отдельное
сопряжение, не имеет отношения к A2DP-колонке — используется только чтобы оба устройства знали друг
друга для RFCOMM). В приложении выбери режим Bluetooth, выбери ПК из списка сопряжённых устройств,
жми "Подключиться". Битрейт Opus для этого режима (звук ПК→телефон и микрофон→ПК отдельно)
настраивается ползунками в шторке настроек — по умолчанию 320/32 kbps, применяется на лету без
переподключения.

**Wi-Fi: качество.** В шторке настроек есть «Качество по Wi-Fi»: «Авто» (по умолчанию) — звук идёт без сжатия, а если сеть
не успевает (рвётся, особенно на 2,4 ГГц или через роутер), сервер сам на ходу переключает сессию на Opus 192 кбит/с;
«Без сжатия» и «Сжатый» фиксируют режим. Порт сервера по умолчанию 45121 (прежний 57120 после перезагрузки Windows может
оказаться внутри зарезервированного диапазона; если порт занят, сервер берёт следующий из 45121–45140).

**Если звук рвётся** — в шторке настроек (шестерёнка) есть ползунок «Буфер воспроизведения»
(по умолчанию 120 мс): запас против рывков сети. Больше — устойчивее, но больше задержка. Приложение
само добавляет запас, если буфер опустел (в логе видно «Недогрузка буфера»), а раз в 10 секунд пишет
в лог состояние буфера. Для Bluetooth разумно начинать с 200–300 мс. Если в Windows для устройства
вывода выставлено 192 кГц, а слушаешь обычную музыку, лучше снизить формат до 48/96 кГц
(«Звук → Свойства → Дополнительно») — на слух то же самое, а трафик по Wi-Fi/USB меньше в 2–4 раза.

**Телефон как отдельный выход звука Windows.** Сервер копирует звук с выбранного устройства вывода
(он при этом продолжает играть и на ПК). Чтобы звук шёл *только* на телефон и в списке «Вывод» Windows
был отдельный пункт, поставь любой подписанный виртуальный аудиокабель (например, VB-CABLE) — виртуальные
устройства нужны драйверы с подписью Microsoft, собственный драйвер я не пишу. Сервер сам находит такой выход
(в списке он помечен ★) и берёт звук с него; в «Звук Windows → устройство → Свойства» его можно
переименовать в имя телефона.

**Громкость** синхронизируется: ползунок громкости выхода, с которого сервер берёт звук (например, «Ruslan Xperia»),
и кнопки громкости на телефоне двигают друг друга (включая mute). При подключении сначала берётся громкость телефона.

**Кнопка на наушниках** работает как медиа-клавиша ПК: одно нажатие — пауза/пуск, двойное — следующий
трек, тройное — предыдущий (реагирует тот плеер на ПК, который слушается клавиатурных медиа-клавиш).

**Микрофон телефона** по умолчанию выключен: включается переключателем в приложении, а на ПК
выбирается устройство, куда он воспроизводится (по умолчанию «не воспроизводить», чтобы не слышать
его в наушниках). Для использования как микрофона в программах выбери выходом виртуальный кабель.

**Брандмауэр.** Если Windows считает сеть «общедоступной» (так бывает с Wi-Fi-хотспотом и подобным),
входящие подключения блокируются — сервер заметит это и покажет кнопку, создающую разрешающее правило
(нужны права администратора).

## Почему так, а не иначе

- **Raw PCM float32 на Wi-Fi/USB, Opus 320kbps на Bluetooth** — на Wi-Fi/USB пропускной способности
  много, поэтому звук идёт вообще без сжатия, бит-в-бит из микшера Windows. Bluetooth Classic
  (RFCOMM) физически не тянет сырой стерео-поток с запасом по джиттеру, поэтому там Opus — но на
  таком битрейте это практически неотличимо от lossless, и работает надёжнее прямого A2DP.
- **Не A2DP/LDAC** — LDAC существует только как кодек профиля A2DP, реализуется Bluetooth-стеком/
  прошивкой, и в него нельзя передать микрофон обратно (A2DP однонаправленный). Поэтому Bluetooth
  здесь — свой RFCOMM-канал с собственным протоколом, а не системное подключение "как колонка".
  Подробности и альтернативы — в PROTOCOL.md.
- **USB через AOA, а не adb и не модем** — adb требует включённой отладки и adb.exe на ПК, модем виден как
  сетевая карта со своими правилами брандмауэра. AOA — штатный «аксессуарный» канал Android: телефон
  приходит как устройство с двумя bulk-эндпоинтами, поверх которых идёт тот же протокол, что и по TCP.
  Цена — один раз поставить драйвер UsbDk (libusb на Windows иначе не может открыть телефон).

## Известные ограничения

- Реконнект есть (2 сек между попытками, детект мёртвого соединения по PING/9 сек), но не покрыт
  тестами на реальных обрывах связи — если заметишь зависания, дай знать через issue.
- Установщик подписан не публичным (коммерческим) сертификатом, поэтому Windows SmartScreen может
  всё равно показать предупреждение при первом запуске на чужой машине — см. ниже, как это исправить
  своим сертификатом.

## Как получить сертификаты для своей сборки

### Android: ключ для подписи APK

```bash
keytool -genkeypair -v -keystore android-app/keystore/release.jks -alias audiobridge \
  -keyalg RSA -keysize 2048 -validity 10000
```
Затем создай `android-app/keystore.properties`:
```properties
storeFile=keystore/release.jks
storePassword=...
keyAlias=audiobridge
keyPassword=...
```
После этого `gradlew :app:assembleRelease` подписывает APK автоматически. Сохрани `release.jks` и
пароли отдельно (менеджер паролей / бэкап) — если ключ потеряется, обновить уже установленное у
кого-то приложение под той же подписью станет невозможно.

### Windows: сертификат для подписи установщика (Authenticode)

Есть три варианта, в порядке усложнения:

1. **Самоподписанный** — быстрее всего, годится, чтобы просто отличать свои сборки от чужих:
   ```powershell
   $cert = New-SelfSignedCertificate -Type CodeSigning -Subject "CN=Your Name" -CertStoreLocation Cert:\CurrentUser\My
   $pwd = ConvertTo-SecureString -String "пароль" -Force -AsPlainText
   Export-PfxCertificate -Cert $cert -FilePath cert.pfx -Password $pwd
   ```
2. **Свой внутренний CA**, если он у тебя уже есть (openssl) — выпусти лист с
   `extendedKeyUsage=codeSigning` и собери `.pfx` (`openssl pkcs12 -export ...`).
3. **Публичный коммерческий сертификат** (DigiCert, SSL.com, Sectigo и т.п.) — единственный
   вариант, который снимает предупреждение SmartScreen у случайных сторонних пользователей;
   требует подтверждения личности/организации и платный.

Вариант 1 и 2 убирают предупреждение только на машинах, где ты сам добавил корневой сертификат
своего CA в доверенные — для остальных Windows всё равно покажет "Windows защитила ваш компьютер".

Подпись и проверка (одинаково для всех трёх вариантов):
```
signtool sign /fd SHA256 /f cert.pfx /p <пароль> /tr http://timestamp.digicert.com /td SHA256 AudioBridgeServer-Setup.exe
signtool verify /pa AudioBridgeServer-Setup.exe
```
