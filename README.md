# Audio Bridge

Я сделал это, чтобы гонять звук с компьютера на телефон (и обратно — с телефона на компьютер идёт
микрофон) с минимальной задержкой, тремя способами на выбор: Wi-Fi, USB и Bluetooth. Полный дуплекс,
без плясок с виртуальными аудиоустройствами и сторонними приложениями с рекламой.

- `pc-server/` — сервер на .NET 8 / WinForms (NAudio для WASAPI, Concentus для Opus, InTheHand.Net.Bluetooth для RFCOMM)
- `android-app/` — Android-приложение на Kotlin + Jetpack Compose/Material 3 (минимум Android 8.0 / API 26)
- `installer/` — Inno Setup скрипт и билд-скрипт для установщика ПК-сервера

Формат протокола между ПК и телефоном и почему кодеки выбраны именно так — в [PROTOCOL.md](PROTOCOL.md).

## Быстрый старт

### 1. ПК-сервер

**Готовый установщик** (проще всего): `installer/output/AudioBridgeServer-Setup.exe` — самодостаточный
exe, .NET рантайм зашит внутрь, ничего доустанавливать не нужно. Ставится без прав администратора в
`%LocalAppData%\AudioBridge`, кладёт ярлыки в меню Пуск и опционально на рабочий стол/автозагрузку.

Собрать установщик самому:
```powershell
powershell -ExecutionPolicy Bypass -File installer\build.ps1
```
(нужен Inno Setup 6 — `winget install JRSoftware.InnoSetup`).

**Или запусти из исходников:**
```bash
cd pc-server/AudioBridge.Server
dotnet run
```

В окне сервера:
1. Выбери устройство, с которого захватывать звук (или оставь "по умолчанию").
2. Выбери устройство, куда выводить микрофон телефона.
3. Нажми **Старт** — поднимутся TCP-слушатель (Wi-Fi + USB), Bluetooth-слушатель и UDP-responder
   для автопоиска сервера из приложения.

### 2. Android-приложение

Установи APK (провод или уже подключённый Wi-Fi-adb):
```bash
adb install -r android-app/app/build/outputs/apk/release/app-release.apk
```
Либо открой `android-app/` в Android Studio и нажми Run.

Приложение не в Play Store, поэтому обновляется само: при запуске проверяет
[GitHub Releases](https://github.com/RRZHD/audio-bridge/releases) этого репозитория, и если там
тег новее установленной версии — показывает баннер "Обновить" (качает .apk из релиза и передаёт
системному установщику). Чтобы выпустить новую версию, подними `versionName`/`versionCode` в
`android-app/app/build.gradle.kts` и опубликуй релиз с тегом `vX.Y.Z` и .apk-ассетом:
```bash
gh release create vX.Y.Z android-app/app/build/outputs/apk/release/app-release.apk --title vX.Y.Z --notes "..."
```

Интерфейс — Jetpack Compose/Material 3, тёмная/светлая тема подхватывается из системной, на
Android 12+ работают динамические цвета. Переключение режима Wi-Fi/USB/Bluetooth — сегментированными
кнопками сверху, статус-карточка с индикатором сразу под ним, сворачиваемый лог снизу, настройки
битрейта — в шторке по иконке шестерёнки.

### 3. Подключение

**Wi-Fi** — ПК раздаёт Wi-Fi (Mobile Hotspot). Выбери в приложении режим Wi-Fi — оно само разошлёт
UDP-broadcast и покажет список найденных серверов в сети (имя ПК + IP); тапни на нужный. Вводить IP
вручную нужно только если автопоиск ничего не нашёл (другая подсеть, файрвол и т.п.) — под списком
есть поле для этого.

**USB** — воткни телефон кабелем, включи USB-отладку. На ПК в поле `adb.exe` укажи путь к нему и
нажми **adb reverse (USB)** — это выполнит `adb reverse tcp:57120 tcp:57120`. В приложении выбери
режим USB, жми "Подключиться" (порт тот же, IP не нужен — коннект идёт на `127.0.0.1`).

**Bluetooth** — сначала спарь телефон и ПК как обычно через настройки Bluetooth (это отдельное
сопряжение, не имеет отношения к A2DP-колонке — используется только чтобы оба устройства знали друг
друга для RFCOMM). В приложении выбери режим Bluetooth, выбери ПК из списка сопряжённых устройств,
жми "Подключиться". Битрейт Opus для этого режима (звук ПК→телефон и микрофон→ПК отдельно)
настраивается ползунками в шторке настроек — по умолчанию 320/32 kbps, применяется на лету без
переподключения.

## Почему так, а не иначе

- **Raw PCM float32 на Wi-Fi/USB, Opus 320kbps на Bluetooth** — на Wi-Fi/USB пропускной способности
  много, поэтому звук идёт вообще без сжатия, бит-в-бит из микшера Windows. Bluetooth Classic
  (RFCOMM) физически не тянет сырой стерео-поток с запасом по джиттеру, поэтому там Opus — но на
  таком битрейте это практически неотличимо от lossless, и работает надёжнее прямого A2DP.
- **Не A2DP/LDAC** — LDAC существует только как кодек профиля A2DP, реализуется Bluetooth-стеком/
  прошивкой, и в него нельзя передать микрофон обратно (A2DP однонаправленный). Поэтому Bluetooth
  здесь — свой RFCOMM-канал с собственным протоколом, а не системное подключение "как колонка".
  Подробности и альтернативы — в PROTOCOL.md.
- **Один и тот же TCP-порт для Wi-Fi и USB** — `adb reverse` просто туннелирует локальный порт
  телефона на порт ПК, поэтому серверу не нужно ничего знать про USB отдельно.

## Известные ограничения

- Реконнект есть (2 сек между попытками, детект мёртвого соединения по PING/9 сек), но не покрыт
  тестами на реальных обрывах связи — если заметишь зависания, дай знать через issue.
- Установщик подписан не публичным (коммерческим) сертификатом, поэтому Windows SmartScreen может
  всё равно показать предупреждение при первом запуске на чужой машине — см. ниже, как это исправить
  своим сертификатом.

## Как получить сертификаты для своей сборки

### Android: ключ для подписи APK

```bash
keytool -genkeypair -v -keystore android-app/keystore/release.jks -alias audiobridge \
  -keyalg RSA -keysize 2048 -validity 10000
```
Затем создай `android-app/keystore.properties`:
```properties
storeFile=keystore/release.jks
storePassword=...
keyAlias=audiobridge
keyPassword=...
```
После этого `gradlew :app:assembleRelease` подписывает APK автоматически. Сохрани `release.jks` и
пароли отдельно (менеджер паролей / бэкап) — если ключ потеряется, обновить уже установленное у
кого-то приложение под той же подписью станет невозможно.

### Windows: сертификат для подписи установщика (Authenticode)

Есть три варианта, в порядке усложнения:

1. **Самоподписанный** — быстрее всего, годится, чтобы просто отличать свои сборки от чужих:
   ```powershell
   $cert = New-SelfSignedCertificate -Type CodeSigning -Subject "CN=Your Name" -CertStoreLocation Cert:\CurrentUser\My
   $pwd = ConvertTo-SecureString -String "пароль" -Force -AsPlainText
   Export-PfxCertificate -Cert $cert -FilePath cert.pfx -Password $pwd
   ```
2. **Свой внутренний CA**, если он у тебя уже есть (openssl) — выпусти лист с
   `extendedKeyUsage=codeSigning` и собери `.pfx` (`openssl pkcs12 -export ...`).
3. **Публичный коммерческий сертификат** (DigiCert, SSL.com, Sectigo и т.п.) — единственный
   вариант, который снимает предупреждение SmartScreen у случайных сторонних пользователей;
   требует подтверждения личности/организации и платный.

Вариант 1 и 2 убирают предупреждение только на машинах, где ты сам добавил корневой сертификат
своего CA в доверенные — для остальных Windows всё равно покажет "Windows защитила ваш компьютер".

Подпись и проверка (одинаково для всех трёх вариантов):
```
signtool sign /fd SHA256 /f cert.pfx /p <пароль> /tr http://timestamp.digicert.com /td SHA256 AudioBridgeServer-Setup.exe
signtool verify /pa AudioBridgeServer-Setup.exe
```
