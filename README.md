# Audio Bridge

ПК ↔ Android, полный дуплекс (звук ПК → телефон, микрофон телефона → ПК), три транспорта:
Wi-Fi, USB (через adb reverse), Bluetooth (RFCOMM). Формат протокола и обоснование выбора
кодеков — в [PROTOCOL.md](PROTOCOL.md).

- `pc-server/` — сервер на .NET 8 / WinForms (NAudio для WASAPI, Concentus для Opus, InTheHand.Net.Bluetooth для RFCOMM)
- `android-app/` — Android-приложение на Kotlin + Jetpack Compose/Material 3 (минимум Android 8.0 / API 26)
- `installer/` — Inno Setup скрипт и билд-скрипт для установщика ПК-сервера

## Быстрый старт

### 1. ПК-сервер

**Готовый установщик** (рекомендуется): скачай/собери `installer/output/AudioBridgeServer-Setup.exe`
— это самодостаточный exe (.NET рантайм зашит внутрь, ничего доустанавливать не нужно), ставится
без прав администратора в `%LocalAppData%\AudioBridge`, кладёт ярлыки в меню Пуск и опционально на
рабочий стол/автозагрузку. Собрать самому:
```powershell
powershell -ExecutionPolicy Bypass -File installer\build.ps1
```
(требует Inno Setup 6 — `winget install JRSoftware.InnoSetup`).

**Или из исходников:**
```bash
cd pc-server/AudioBridge.Server
dotnet run
```

В окне:
1. Выбери устройство, с которого захватывать звук (или оставь "по умолчанию").
2. Выбери устройство, куда выводить микрофон телефона.
3. Нажми **Старт** — поднимутся TCP-слушатель (Wi-Fi + USB), Bluetooth-слушатель и UDP-responder
   для поиска сервера из приложения (см. "Discovery" в PROTOCOL.md).

### 2. Android-приложение

APK уже собран и подписан релизным ключом: `android-app/app/build/outputs/apk/release/app-release.apk`.

Установка через adb (провод или уже подключённый Wi-Fi-adb):
```bash
adb install -r android-app/app/build/outputs/apk/release/app-release.apk
```
Либо открой `android-app/` в Android Studio и нажми Run (debug-вариант).

Интерфейс — Jetpack Compose/Material 3 (тёмная/светлая тема по системной, поддержка
динамических цветов на Android 12+): переключатель режима Wi-Fi/USB/Bluetooth сегментированными
кнопками, статус-карточка с индикатором, сворачиваемый лог, шторка с ползунками битрейта (иконка
шестерёнки в шапке).

### 3. Подключение

**Wi-Fi** — ПК раздаёт Wi-Fi (Mobile Hotspot). В приложении выбери режим Wi-Fi — оно само
разошлёт UDP-broadcast и покажет список найденных серверов в сети (имя ПК + IP); тапни на нужный.
IP вручную нужен только если автопоиск ничего не нашёл (другая подсеть, файрвол и т.п.) — под
списком есть поле для этого.

**USB** — воткни телефон кабелем, включи USB-отладку. На ПК в поле `adb.exe` укажи путь
(по умолчанию подставится `F:\platform-tools\adb.exe`, если он есть) и нажми **adb reverse (USB)** —
это выполнит `adb reverse tcp:57120 tcp:57120`. В приложении выбери режим USB, жми "Подключиться"
(порт тот же, IP не нужен — коннект идёт на `127.0.0.1`).

**Bluetooth** — сначала спарь телефон и ПК как обычно через настройки Bluetooth Windows/Android
(это отдельное сопряжение, не имеет отношения к A2DP-колонке — используется только чтобы оба
устройства знали друг друга для RFCOMM). В приложении выбери режим Bluetooth, выбери ПК из списка
сопряжённых устройств (кнопка обновления списка рядом), жми "Подключиться". Битрейт Opus для этого
режима (звук ПК→телефон и микрофон→ПК отдельно) настраивается ползунками в шторке настроек — по
умолчанию 320/32 kbps, применяется на лету без переподключения.

## Почему так, а не иначе

- **Raw PCM float32 на Wi-Fi/USB, Opus 320kbps на Bluetooth** — на Wi-Fi/USB пропускной способности
  много, поэтому звук идёт вообще без сжатия, бит-в-бит из микшера Windows (важно, раз приёмник —
  Xperia 1 IV с хорошим ЦАПом). Bluetooth Classic (RFCOMM) физически не тянет сырой стерео-поток
  с запасом по джиттеру, поэтому там Opus — но на таком битрейте это практически неотличимо от
  lossless, и работает надёжнее прямого A2DP.
- **Не A2DP/LDAC** — LDAC существует только как кодек профиля A2DP, реализуется Bluetooth-стеком/
  прошивкой, и в него нельзя передать микрофон обратно (A2DP однонаправленный). Поэтому Bluetooth
  здесь — свой RFCOMM-канал с собственным протоколом, а не системное подключение "как колонка".
  Подробности и альтернативы — в PROTOCOL.md.
- **Один и тот же TCP-порт для Wi-Fi и USB** — `adb reverse` просто туннелирует локальный порт
  телефона на порт ПК, поэтому серверу не нужно ничего знать про USB отдельно.

## Известные ограничения / что не сделано

- Реконнект есть (2 сек между попытками, детект мёртвого соединения по PING/9 сек), но не покрыт
  тестами на реальных обрывах связи — если заметишь зависания, дай знать.
- Собранный installer подписан Authenticode-сертификатом с приватного code-signing CA (не публичный
  CA из программы доверенных корневых Windows) — подпись валидна и проверяема (`signtool verify`),
  но SmartScreen у сторонних пользователей, у которых не установлен корневой этого CA как
  доверенный, всё равно может показать предупреждение "Windows защитила ваш компьютер". На машинах,
  где корневой сертификат уже доверенный (свои устройства), предупреждения не будет. Приватный
  ключ сертификата в репозитории не хранится и не хранится локально после сборки — см. "Подпись
  установщика" ниже.

## Подпись релизной сборки (Android)

Релизный keystore (`android-app/keystore/release.jks`) и пароли к нему (`android-app/keystore.properties`)
**сознательно не в git** — это публичный репозиторий, а закрытый ключ приложения раскрывать нельзя
(и Google Play в любом случае требует, чтобы он оставался приватным). Оба пути в `.gitignore`.

Чтобы собрать свою подписанную сборку:
```bash
keytool -genkeypair -v -keystore android-app/keystore/release.jks -alias audiobridge \
  -keyalg RSA -keysize 2048 -validity 10000
```
и создай `android-app/keystore.properties`:
```properties
storeFile=keystore/release.jks
storePassword=...
keyAlias=audiobridge
keyPassword=...
```
После этого `gradlew :app:assembleRelease` подписывает APK автоматически (без файла — соберётся
неподписанный release APK, `assembleDebug` собирается debug-ключом Android как обычно, отдельной
настройки не требует).

**Важно:** если этот keystore потерян, обновить уже установленное приложение с тем же
`applicationId` под той же подписью будет невозможно — сохрани `release.jks` и пароли отдельно
(менеджер паролей / бэкап), не полагаясь на то, что они остались в рабочей копии.

## Подпись установщика (Authenticode)

`installer/output/AudioBridgeServer-Setup.exe` подписан code-signing сертификатом (`extendedKeyUsage
= codeSigning`), выпущенным на приватном CA — приватный ключ живёт только там же, где и сам CA, и
никогда не попадает ни в git, ни на диск разработческой машины дольше, чем нужно на один вызов
`signtool sign`. Порядок для своего CA:

```
signtool sign /fd SHA256 /f cert.pfx /p <пароль> /tr http://timestamp.digicert.com /td SHA256 AudioBridgeServer-Setup.exe
signtool verify /pa AudioBridgeServer-Setup.exe
```

Такой сертификат снимает предупреждение SmartScreen только на машинах, где корневой сертификат
этого CA уже установлен в доверенные — для случайного стороннего пользователя без публичного
(коммерческого) code-signing сертификата от CA из программы доверенных корневых Windows
предупреждение всё равно будет появляться.
